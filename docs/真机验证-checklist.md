## 如后续恢复验收的现场执行顺序

1. 用 [离线检查](统一测试前-离线检查.md) 核对当前源码和聚合结果；确认加载路径、端口、identity 和默认开关。
2. R2 先跑 G01–G07，再补 S01/V01/A01；只看数字、枚举、id 和安全观察结果，维持 dry-run。
3. 验证 U01 浏览器与原生 Electron。按明确范围切换真实输出后再做 O01/O02，不能因为一条 test_say 成功就勾选全部声音项。
4. 仍受额外门控的乘员/弹药、V2/free-text 保留原策略；缺少相应证据时不自动放开。自由文本当前实现仍阻断真实播报，本清单不授权改产品行为。
5. 用模板回填每项 ID 的通过/失败/未观察，列证据和剩余缺口。R3 在当前源码离线聚合门禁复验通过后执行。
6. 停止仅由本次测试启动的服务；核对端口释放、外部数据层保留、配置/状态保留。不得静默遗留后台进程。

## 安全证据与命令

从独立插件仓库执行现有只读监控与交接入口：

```powershell
uv run python tools/live_monitor.py --json
uv run python tools/final_smoke_packet.py
```

需要导出当前 evidence 时，按工具帮助指定本地日志目录，报告只保存计数、状态、时间和确认标记，不附 raw 玩家名/聊天/HUD/combat/awards 或模型回复原文：

```powershell
uv run python tools/final_smoke_evidence_gate.py --help
uv run python tools/final_smoke_evidence_gate.py --safe-transcript-template
uv run python tools/final_smoke_evidence_gate.py --from-live-monitor local_test_logs/live_monitor_final.json --output local_test_logs/final_smoke_evidence.json
uv run python tools/final_smoke_evidence_gate.py local_test_logs/final_smoke_evidence.json
```

人工确认只在实际完成后填写，例如 `--confirm-critical-replaced-stale-warning`、`--confirm-user-chat-quiet-window`、`--confirm-short-tts-single-line`、`--confirm-mode-domain-boundary`。离线 `--rehearsal-output-dir` 输出仅证明填报流程，不作真机 evidence。

现有 final-smoke evidence gate 只验其已定义的 P1 schema，**不会自动覆盖本表新增的全部陆战/设备验收行**；G01–G07 等还需在 [结果模板](真机测试结果-template.md) 中记录实际观察和证据位置。
