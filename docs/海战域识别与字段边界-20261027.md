## 本轮范围与成本

用户明确要求先完善海战域识别和字段边界。检查发现顶层把无仪表兜底为 naval、任意其他有效兵种当 ground，加工层却单独支持 ship/fleet；同时无效直升机标记、跨域缓存和原始运动/乘员字段可能越界。

采用保守方案：共享有效兵种分类、未知域降级和只读地图兼容；不新增事件/播报。完整舰艇仪表、自动重生及专项事件需要字段语义和证据，继续暂缓；若延后本轮，原兜底误识别与残留字段风险仍存在。

新增运行成本限于常数级白名单/字段投影和一个来源代码；分类复用现有轮询，不新增扫描、后台进程、依赖、配置、持久状态、LLM/token 或真实输出调用。数据层合同语义更新为 v1.10，插件分发版本未改，宿主核心未改。

## 域识别与字段矩阵

| 输入/字段 | 当前行为 | 证据与限制 |
|---|---|---|
| 战局外 | 优先 menu，忽略机库仪表 | 不将机库选中载具当作进场 |
| 有效兵种 air/tank/ship/fleet | 顶层与 processed 共用白名单；air 再分直升机，tank 为 ground，ship/fleet 为 naval | ship/fleet 沿用兼容合同代码，当前游戏舰艇正向字段未验，不声称已采到真实样本 |
| 无效/缺失/未知兵种、仅有地图 Player 图标 | unknown；不沿用旧载具，也不按 ground_model 猜陆海或按 aircraft 猜固定翼 | 通用地图卡继续可见，图标不能确认舰种 |
| domain_source | 白名单来源代码；未知文本不透传 | HTTP 侧为旧 naval 缺证据/冲突添加 unconfirmed_naval/conflicting_domain，域均降级 unknown |
| 海战/未知域的飞行、坦克、直升机仪表与 flags/profile | 数据层不加工，HTTP 侧在数值转换前再次丢弃；不套用飞机 profile | 原始 JSON 留在本地 raw，不能把空速当航速、乘员当舰员、待发弹当舰炮余弹 |
| 旧加工缓存、未知接近事件 | 源头不输出与当前域不一致的 processed；unknown 隐藏接近事件，HTTP 侧再清理 | 不把旧域数据晚播成新事实，原共享 owned HUD/战绩合同保留 |
| 静止/运动、乘员生命信号 | 只消费已有明确语义的有效域；未知速度不当作静止残骸；乘员仅陆战使用 | 舰艇速度/乘员不确认死亡或重生，海战自动重生模型未实现；已确认自己的 HUD 阵亡仍有效 |
| 地图态势 | naval 显示海战卡，unknown 显示“地图态势（载具未确认）” | 复用成功采样计龄/生命/尺度边界，过期或不可靠值隐藏，不新增播报 |

完整来源枚举和字段说明见 [后端接口合同](../data_layer/data_process/后端接口文档.md#载具域-domain--domain_label)。旧数据层 naval 声明缺少有效 ship/fleet 时降为未知，保留通用地图只读体验，不继续启用海战专项输入。
