## fuel_consume 的实际接线

1. 来源候选为 **`/indicators` 的 fuel_consume / fuel_consume1**。目录均为 f64、unit 空白；不是 `/state` 中带 kg 的燃油质量。README 把无编号字段描述为 kg/h、仅部分飞机提供；这是作者声明，尚无本轮实机单位验证。编号 1 的含义、通道覆盖及能否求和未知，不推成第二发动机或全机总油耗。
2. **内置 ID 存在接缝不一致**：scraper `key_to_id`（67–109 行）加 indicators_ 前缀；目录的 ID 是 `indicators_fuel_consume` / `indicators_fuel_consume1`。`load_fields`（1268–1275 行）直接反序列化；`extract_fields`（1940–1957 行）按 field.id 写 RawFrame。`inject_derived_fields`（567–613 行）却只读取 `fuel_consume`，没有别名改写，也不读取编号通道。因此该内置目录不能直接命中所声称的原生优先路径；自定义目录改名可能改变结果，不能外推所有安装。
3. 上游原生优先测试（2468–2488 行）手工插入无前缀 `fuel_consume`，不能证明目录→提取→派生链路接通。本轮按其提取语义做 Python 重建，确认只出现带前缀键；**没有执行 Rust 测试或运行第三方程序**，不把静态发现包装为上游实机故障复现。
4. 当前我们没有原生油耗专用字段：仍只在 `Indicators.raw` 保留。处理器按 `/state` 的燃油质量差估率，不消费上述 raw；插件 BattleState 只接现有比例/余时，不接原生油耗、压力或数据层 burn-rate 字段。P1a 空战五事实只含燃油比例，P1b 不扩白名单。

## 单位与派生边界

| 字段/来源 | 单位证据与换算 | 当前用途/缺口 |
|---|---|---|
| state.Mfuel, kg / Mfuel0, kg | 原键明确 kg；分别映射 fuel_kg / fuel_full_kg | 既有比例/质量差估率输入；Mfuel0 不能直接称机型油箱容量或可用航程 |
| indicators.fuel | 目录无单位，不能当 kg/升/燃油比例 | 仅 raw；不得替代质量或比例输入 |
| indicators.fuel_consume / fuel_consume1 | 目录空白；无编号字段 README 称 kg/h，编号通道语义未知 | 不接新可信字段，不求和；原生优先意图与默认接线分开 |
| BYOH fuel_consume_calc / fuel_flow | **虚拟字段**：质量差除时间再乘 3600，EMA α=0.25；fuel_flow 意图优先原生 | 不属于游戏原生接口；原生直拷无单位换算，不能借虚拟统一名证明原生单位 |
| BYOH fuel_time 示例 | 公式 `(mfuel_kg / fuel_flow) * 3600`，结果秒 | 仅在 kg 与 kg/h 且同一状态时成立；不是返航距离或安全保证 |
| 我们 fuel_burn_rate_kgs / fuel_remaining_sec | kg/s；EMA α=0.2；余时=kg÷(kg/s)，不乘 3600 | 合成 500→499 kg、间隔 1 s：1 kg/s、499 s；BYOH 差分公式应为 3600 kg/h，量纲核对并非实机标定 |
| fuel_pressure / fuel_pressure1、oil_pressure / oil_pressure1 | 目录空白；没有 psi/bar/atm 的确证 | 仅 raw；不报警、不按发动机编号猜通道 |
| state.Wx, deg/s | 原键 deg/s，BYOH unit 却仅 ° | 目录单位推断丢了 /s；保留现有 roll_rate_dps 合同 |
| state.thrust N, kgs | 目录因匹配 kg 字串写成 kg | 是推力键，不是质量/油耗；沿用 thrust_kgs 名称，若转 N 需单列物理单位合同 |
| state.manifold pressure N, atm | 原键明确 atm，目录 unit 空白 | 现有 manifold_pressure_atm；不能用空白认定无量纲 |

表针边界同样重要：`rpm_hour/min`、高度指针、压力/温度指针不能因为数值或名字就直接套物理单位。[官方 CDK 座舱文档](https://wiki.warthunder.com/cdk/234-3d-models-for-cockpits) 说明的是模型动画和量程，列有双针 RPM 的旋转及仪表初末位置；**不是 HTTP JSON 的统一单位规范**。它提醒必须区分表针与物理量，不能反过来宣称所有同名 JSON 都是角度或归一化比例。

我们现有 `_max_engine_temp` 已把 `water_temperature[_N]_hour` 纳入 max 聚合，再由机型启发式分配水温/涡轮温度；这是历史映射事实，BYOH 目录没有验证其通用摄氏含义。`_min` 当前仅 raw，不能随意当同温度的另一路。A2 温度分项实施前仍须核对具体通道/机型/同帧来源，不因本轮发现而改现有告警。

## 失效与生命周期边界

| 边界 | BYOH 固定版本证据 | 我们现状与未来燃油合同要求 |
|---|---|---|
| 请求失败/坏 JSON | Background cache 是 endpoint→JSON，无 TTL/成功时间；失败不删除旧值，extract 不按 valid 拦截数值（1630–1690、1839–1900、1940–1957 行） | 既有服务有短失败保留数值/清 flags 与失效重置，P1a 查来源年龄；但不能据此声称单个油耗或估算已具独立龄期 |
| 分端点采样 | 每端点独立线程，读取缓存拼帧；旧 indicators 可与新 state 合并 | 原生率若将来参与余时，必须证明同域/同载具/同生命及时间关系；不能只用 HTTP 响应/组轮询时间盖章 |
| 恒油/熄火/节流 | EMA 在燃油变化时更新，恒油可保留；原生零值存在即优先，不检查正值后再选备用 | 我们恒油也沿用旧率，合成第二/第三次余时均 499 s；缺最后有效估算时间/质量，不能展示成实时倒计时。零可为有效工况或失效，未证前不能计算无限续航/自动回退 |
| 加油/新生命/换机 | 油量增加清 EMA；DerivedState 在客户端构造时初始化，未见显式生命/机型重置 | 我们有补给、类型切换及服务离场/确认重生等重置，但载具独立 sample-life 仍 unverified；新生命等油量/更低油量不能靠 refuel 分支证明安全 |
| 缺失/非法/负数 | 目录 f64 只约束提取类型；原生流率路径无统一正值/质量判据；缓存缺时不等于清 EMA | 新字段需严格数值、拒 bool/数字字符串/非有限；区分缺失、零、负数、单位不明、过龄。既有 `_num` 可把 bool/string 转 float，不能直接用来宣称新合同已满足 |

因此 BYOH 可提供字段发现、差分算法与公式参考，不能整体搬来当作可靠时效/生命保护。我们本轮也没有修复或增加上述运行合同，现有低油量仍按比例判据，全部真实输出边界维持。
