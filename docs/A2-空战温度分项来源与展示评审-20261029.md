## 解析与有效性：已经核实的行为

1. `_max_engine_temp` 遍历无编号及 1..8，各取无后缀与 `_hour`，跳过 <=-200 占位，最大后统一四舍五入一位。`_min`、9 号及更大通道未参与；同一通道无后缀与 _hour 不一致时取大值，没有冲突或胜出键元信息。因此它不是“第 N 发当前温度”，也不证明所有发动机都已采到。
2. 固定翼 jet 启发式为 air、非 heli 且不存在 mixture/manifold_pressure；检查的是键存在性。即使 mixture=null 也会压住 jet 分支；反过来只有 head_temperature 却无上述键时头温被置空。未知/异常机型不能据此获得水冷/气冷/喷气的强分类。
3. 数据层 `_num` 可把数字字符串/bool 转 float；max 聚合不先拒 NaN/Infinity，NaN 还可能因遍历位置留下来。插件解析拒 bool，但上游已转换的 1.0/110.0 仍会进入；非有限值也可传到 BattleState。新展示必须独立检查原始输入类型/有限性/占位，不能宣称历史解析器已经全面严格化；本轮不改这些旧行为。
4. `_parse_engines` 的油温来自带 C 的 state 键，但只有油温键而没有编号建立键时 engines 可能为空。新切片遇此情况应未知，不从原始键临时补造发动机实例，也不回退 indicators。只显示已观测有效通道，不能称全机最高温/剩余寿命。

## 来源年龄、缓存和生命边界

| 边界 | 当前事实 | 对新展示的约束 |
|---|---|---|
| indicators 与 state 顺序 | 探针先请求 indicators + map_info，再拉 state；processed 用本次 ind 处理，但没有独立温度通道时间/计数/胜出键 | 不能把响应同包、meta.fast 或 vehicle 年龄叫作独立温度样本证明 |
| state 短失败 | 新 indicators 可更新；旧 processed 数值在保护窗内保留，flags/alerts 清空，vehicle 成功样本时间不更新 | 合成观测出现 indicators 水温150、processed水温90、vehicle age=1；仅查源龄<=5和ind.valid不足以证明两者同次加工 |
| 探针短失败 | 宽限期早退，旧 indicators/processed 可留在缓存；海战的独立仪表元信息不适用于固定翼温度 | 不从海战元信息拼造空战温度成功采样；原生 state 油温沿自身 vehicle 年龄，不伪造为实时连续读数 |
| 新增读取 | dashboard/SDK读取不产生新的采样或清除缓存 | 新投影不得 feed/reset、推进确认、更新历史、写配置或标新时间 |
| 生命周期 | 现有离场/确认重生/类型切换有处理器重置；vehicle 独立 sample-life 仍 unverified | 原生油温只表达最近有效当前快照；离线/离场/阵亡/回放/过期/未知年龄/未来时钟收起，不新增生命绑定承诺 |

state 油温直接来自同一个 vehicle 快照，避开 indicators→processed 的跨次加工接缝；这不让它自动拥有当前尚未提供的独立生命校验。首版保留 unverified 限制，不修改通用采样合同或继承海战的 sample-life 标签。

## 既有过热归因问题：已复现，未修复

[过热 Detector](../detectors/condition/flight_safety.py) 的 `_pl_overheat` 依 water/head/turbine/oil 顺序选首个非空温度，未按实际触发 flag 选择。数据层又把水温/缸头/涡轮共用 engine_overheat 命名空间，油温使用 oil_overheat 命名空间。

本轮合成输入：水温80、油温150，测试专用 cfg 仅设 oil_temp_warn_c=100，处理器只产生 oil_overheat。经当前解析器与实际 Detector 三次确认，候选仍带 `temp_source=water_temp_c, temp_c=80`。**这里的 100 仅为合成复现输入，不是推荐机型阈值。** 结果证明候选温度归因有误，不证明过热事件本身是假警、已经投递或实际模型已经说错；本轮未调用模型或测试最终投递。

建议下一开发任务先单独修复这一接缝：仅在标记与温度可唯一对应时附具体温度；通道混合、多个标记或无法确定来源时省略具体 temp_source/temp_c，保留已有过热事件/等级/确认逻辑和输出闸。不可在插件重算 profile 阈值来猜因果，不把“首个非空”改为“最高数值”（不同温度类别不能如此比较），也不借此新增告警。具体修复须单独 review 和完整相关链路回归后交付。

### 原生油温切片的最小合同（待实现）

1. 仅 domain=air；复用 P1a 当前 vehicle 来源/响应时效规则，不扩 P1a五事实/P1b三视图。固定最多8个 canonical index 通道，严格核对 `vehicle.engines[].index/oil_temp_c` 与对应 `vehicle.raw[oil temp N, C]` 的类型/数值；缺原始字段、规范化缺失、重复/非法编号或数值冲突均降级，不能从别的来源补齐。
2. 数字字符串/bool/非有限拒绝；0与合理负值不当缺失；<=-200沿既有占位兼容规则视为不可用（数据可用性过滤，不是安全温度阈值）。畸形/超规格输入不给具体值，不按现实常识临时换算或认定安全区间。
3. 返回有界状态和“已观测有效通道最大值/观测有效通道数/固定来源标签”，不带 raw、完整通道对象或机型/玩家标识。未覆盖/缺失通道要提示，禁止把部分有效最大值叫全机最热发动机。与 processed.oil_temp_c 不相等时不强行融合，两者本来来自不同接口；首版仅 state 标签。
4. 在现有 **诊断→高级详情→飞行诊断** 中加只读行与来源说明，未知清楚显示；复用现有面板，不新建仪表卡、设置、自动 action、趋势图或告警。收益是诊断可见性，不宣传为新增主动副驾驶或具体过热原因。
5. 同一局/新生命重复读取不留历史、不推进 FSM/计数/冷却；既有温度告警输入/阈值、发言和全部输出闸不变。载具独立生命绑定仍 unverified；被跳过现场项不因本项恢复为研发阻塞。

成本上限建议：最多8个字段组的常数级投影，一份固定结果，UTF-8序列化目标<=512 bytes；单投影1000次暖态 p95<=2 ms。**这是未来目标，本轮未实现/未测量该投影**；不是完整面板/SDK延迟或堆内存上限。新依赖、轮询、网络、线程、持久化、事件/模型调用/token增量均为0；若需要新的 indicators采样/生命周期合同或扩模型，已超此范围，先独立评审成本。
