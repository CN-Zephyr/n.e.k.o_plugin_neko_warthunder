## 来源、覆盖与复现

来源为社区 [gszabi99/War-Thunder-Datamine](https://github.com/gszabi99/War-Thunder-Datamine)，固定提交 `af0cce561a73704e30c1df66eff06209bcc3f035`，该仓库 version 为 `2.59.0.92`。本机游戏版本未核实。固定 [舰艇目录](https://github.com/gszabi99/War-Thunder-Datamine/tree/af0cce561a73704e30c1df66eff06209bcc3f035/aces.vromfs.bin_u/gamedata/units/ships) 含 **734 个顶层 .blkx 文件**；全部读取并核对 Git blob SHA、文件长度和 JSON 结构，共 151,718,241 原始字节。`debris/`、`weaponpresets/` 子目录不在本期范围。

734 是目录配置数，包含 AI、场景单位和变体，**不是可玩舰艇数、独立舰种数或实际游戏支持数量**。本期只读取这些文件的直接字段，不展开 include/继承、武器预设、改装或其他文件，因此缺失保持 null，不能当成最终生效参数。`typeDestroyer` 等是源码类型码，不能直接当历史舰种/蓝水近岸分类。

运行资料库为 [contract/naval_static_catalog.json](../contract/naval_static_catalog.json)，schema_version=1，**505,006 字节**，SHA-256 `58ddeadf8921dfea3c47c8f145ad416273e4252316e58f77170202e021b04cbd`。每条记录保留精确文件 ID、blob SHA、源文件字节数和固定静态字段。原始文件只保留在本轮审计目录，不随插件运行分发。

手动离线提取器 [tools/build_naval_static_catalog.py](../tools/build_naval_static_catalog.py) 接受固定提交 manifest 或已有 catalog 作为 manifest；先核实全部输入，再写完整输出。输入验证失败时不写出部分资料库，不更新原 vehicle_profiles、不访问游戏或网络。输出固定 UTF-8/LF 字节，报告 hash 针对实际输出字节，避免平台默认换行差异；本轮实际执行环境为 Windows，未执行 Linux 验证。本轮从交付 catalog 重新提取 734 文件，得到逐字相同输出，见 [目录审计](../../archive/naval-static-20261029/catalog-audit.json)。

```powershell
uv run --offline python tools/build_naval_static_catalog.py --source-dir ../archive/naval-static-20261029/datamine-sources --manifest contract/naval_static_catalog.json --out ../archive/naval-static-20261029/catalog-rebuilt.json
```

`--source-dir` 也可指向包含相同固定提交文件的本地 Datamine checkout；缺失/改动/校验不符即失败。本期一次性下载四路并发，运行态无网络、后台更新、额外轮询、配置或依赖。

## 静态字段映射与覆盖

所有 `_config` 数字只保留源码数值，不添加舰艇单位、不换算、不解释物理范围。计数是配置结构的计数，不是当前运行数量或状态。以下覆盖数量针对 734 条直接记录；“未收录”包括缺字段或未通过严格格式检查，不用 0 补齐。

| 静态字段 | Datamine 直接来源 | 有效记录 | 边界 |
|---|---|---:|---|
| type_code | type | 650 | 内部类型码，不推断玩家舰种 |
| move_type | moveType | 731 | 配置运动类型，不能确认实时 domain |
| economic_class_code | expClass | 730 | 配置分类码，不当实时兵种/战斗等级 |
| mass_empty_config | ShipPhys.mass.Empty | 655 | 配置值，单位、改装与实际排水量未验 |
| forward_speed_config / reverse_speed_config | maxFwdSpeed / maxRevSpeed | 各 731 | 独立保留，与物理模型速度不合并，不当当前航速 |
| engine_forward_speed_config / engine_reverse_speed_config | ShipPhys.engines.maxSpeed / maxReverseSpeed | 各 648 | 模型配置值，不推断 m/s、节或倒车能力 |
| engine_entry_count | ShipPhys.engines.engine 条目 | 650 | 配置发动机条目数，单对象需明确来源；不是当前运转发动机数 |
| propulsion_count | engine 内有效 propeller 的去重数量 | 649 | 不假设发动机与推进器一一对应；任一来源不完整则未知 |
| crew_station_count | tank_crew.sailorN 分区 | 649 | 配置分区数，非当前存活岗位数 |
| crew_distribution_total | 所有直接 sailorN.crew 严格整数合计 | 621 | 配置分区舰员合计，非当前/最大/界面舰员，也不补齐继承/改装 |
| min_alive_crew_config | tank_crew.minCrewMemberAliveCount | 649 | 静态配置项，不作为实时阵亡阈值 |
| min_repair_crew_config | tank_crew.minCrewMemberRepairCount | 643 | 静态配置项，不生成维修可用性或建议 |

例：[Fletcher 源文件](https://github.com/gszabi99/War-Thunder-Datamine/blob/af0cce561a73704e30c1df66eff06209bcc3f035/aces.vromfs.bin_u/gamedata/units/ships/us_destroyer_fletcher.blkx) 与 [PT-6 源文件](https://github.com/gszabi99/War-Thunder-Datamine/blob/af0cce561a73704e30c1df66eff06209bcc3f035/aces.vromfs.bin_u/gamedata/units/ships/us_pt6.blkx) 分别有 2/3 个发动机条目，不能把实时一个 rpm 标量直接分配给多机。配置项存在不代表当前载具、版本和改装与该文件一致。

## 四项实时候选与静态资料的边界

沿用已核实的 [游戏遥测网页源码](https://github.com/gszabi99/War-Thunder-Datamine/blob/af0cce561a73704e30c1df66eff06209bcc3f035/webUi.vromfs.bin_u/index.html) 通用键，以及本地 WarThunderClient 解析路径；没有新增舰艇实时字段或放宽 v1.11 采样合同。

| 实时原始键 → 规范化路径 | 静态相关路径 | 映射结论 |
|---|---|---|
| speed → indicators.speed | maxFwdSpeed/maxRevSpeed、ShipPhys.engines.maxSpeed/maxReverseSpeed | 配置速度不等于当前航速；没有已验证的直接映射、单位或换算 |
| compass → indicators.heading_deg | 无直接静态对应 | 航向是动态事实，不能从质量、舰型或静态模型补出 |
| rpm → indicators.rpm | ShipPhys.engines.engine / propeller 结构 | 仅结构参考，不知道实时标量对应发动机、轴、推进器还是表针，也不从多机配置拆分读数 |
| throttle → indicators.throttle | ShipPhys.engines.speedToTime/reverseSpeedToTime 加速模型 | 模型时间曲线不等于当前操纵量、百分比或车钟，不做反推 |

映射代码位于 [只读投影](../adapters/naval_static_reference.py)。静态资料不写入 BattleState/processed/flags，不参与 Scenario/Detector/Arbiter/Dispatcher，不生成新事件、阈值、舰员状态、损伤/进水、死亡或自动重生判断。`game_version_verified`、`live_values_enriched`、`naval_semantics_verified` 和 `real_output_enabled` 始终 false。

## 精确关联与 UI

- 仅在原有海战/相关未知域诊断范围展示静态资料卡，放在高级详情。资料范围可以展示，但不借此确认载具域。
- 只有七期独立采样 status=ready、sample_life_bound=true，且规范化 vehicle_type 与原始 indicators.raw.type 的解析末段一致，才允许精确 ID 查表。无大小写折叠、别名/家族/模糊匹配、文件后缀裁剪，不回退 cached processed/vehicle_type。
- 旧生命/旧战局/过期/失败/阵亡/回放与 legacy 采样不关联旧载具。未知或未收录 ID 不回显原文、不套默认参数；来源文件丢失/非法/过大时整库降级，不沿用部分资料。
- 卡片只展示固定提交/版本/覆盖范围、规范 ID/类型码和配置发动机/推进器/舰员分区计数；清楚标注“静态配置·非实时”。不显示未经确认单位的质量/速度配置或实际仪表值，无动作/配置写入/播报。
- catalog 最多 2 MiB、2000 条，当前约 493 KiB；每个 worker 首次需要时读取校验一次并缓存，只做精确查表，DTO 不带整库。更新资料需重建审核后随代码同步并重启插件；不后台拉取、在线更新或注入 prompt。
