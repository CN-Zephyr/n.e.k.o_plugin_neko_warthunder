## 范围、成本与方案

当前卡片原先只证明检测已确认，需另查活动页才知道候选去了哪里。采用保守方案：复用现有候选、Arbiter 决策和 DispatchObserver 阶段记录，按不含身份的本地随机标识精确关联，只读显示。延后方案维持原卡；完整跨会话历史与持久跟踪不在本轮范围，避免增加存储和生命周期复杂度。

最多保留两个观察、各三个有限字段摘要；普通模式也可查看，不依赖 debug 开关或 20 条活动历史。复用已有轮询与锁，不新增遥测请求、依赖、后台服务、配置、持久状态、LLM/token 或真实推送。每次新确认才生成随机标识，缓存轮询不生成新标识或额外事件。

本轮 7 个运行文件：`__init__.py`、`adapters/dispatch_observer.py`、`adapters/runtime_timeline.py`、`core/arbiter.py`、`core/contracts.py`、`detectors/discrete/naval_situation.py`、`ui/panel.tsx`。不改变数据层、确认阈值、事件 payload、相等性、优先级/冷却/仲裁策略、投递序列化或真实输出政策。

## 结果与只读边界

| 展示 | 依据 |
|---|---|
| 候选已生成 | 本次确认的实际 detector_candidate；显示确认时的成功采样序号，不把持续存在期间的新序号当作新的确认 |
| 已通过仲裁 | 实际 arbiter_allowed，不代表已记录或已发声 |
| 仅 dry-run 记录 | 同一关联标识的 dispatcher_dry_run，未提交语音 |
| 未进入记录的原因 | 实际限流、冷却、类别偏好关闭、手动/自动暂停、场景拦截、单槽替代、预判过期、候选失效或真实输出阻断；无阶段证据则明确“尚无结果”，不根据全局 dry-run 推测成功 |
| 旧记录隔离 | 当前已完成进度中的标识精确匹配；来源失效、新战局/生命、未处理新采样、重新确认和停用不冒用旧结果；迟到旧决策/记录不能附到新确认 |
| 普通模式 | 即使 debug 关闭、活动历史滚出或最新输出被其他事件覆盖，仍保留两类各最近一次结果；不扩成无界历史 |
| 隐私/并发 | 摘要仅含受控阶段/原因、服务端时间/序号、随机标识和合法采样序号；原始文本/身份/payload 不进入摘要。使用原 timeline 锁返回分离副本，读卡不推进检测或改动仲裁 |

BattleEvent 的可选 trace_id 只用于本地诊断；仅海战 32 位小写十六进制标识可贯穿记录。payload、to_dict()、repr 和相等性均不包含该诊断字段。无标识的旧记录不按 event_id 强行关联；未知原因降为有限 unknown 码，不把原始原因文本塞入卡片。
