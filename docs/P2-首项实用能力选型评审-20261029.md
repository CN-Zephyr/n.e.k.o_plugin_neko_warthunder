### 选型用的实际代码证据

- [处理器 `_process_ground`](../data_layer/data_process/wt_processor.py)：待发弹先见正数基线再降为零才锁存 `ammo_empty`，补弹回正数解除；`ammo_low` 使用本次出生观测最大待发弹量与数据层比例参数，**不是**全车余弹或已知弹架容量。插件还有两次进入/退出确认，见 [FSM](../detectors/_base.py)。
- [服务 `_poll_fast` / `_meta_locked`](../data_layer/data_process/wt_server.py)：`meta.fast` 为组轮询元信息，成功/尝试与 `meta.vehicle` 成功采样不能混同；`/state` 短暂失败可能保留数值但清空 flags，出生保护也会清旗。因此“没有耗尽标记”不能解释为“肯定没打空”或“必定没建立基线”。载具独立 sample-life 仍未证实，沿用 P1a 的 `unverified`，不从响应 life 补造证明。
- 燃油估算在实际油量下降时更新指数平滑耗油率；油量不变时可能沿用原估计，加油重置。当前传输没有独立的“最后一次有效油耗估算时间/置信度”；燃油比例有效不证明续航估计也有效，余时不等于返航航程或安全着陆保证。现有低油量判据仍按比例，不能改成新的倒计时阈值。
- 温度先按现有类型识别分为水温/缸头/涡轮排气/油温；[遥测解析](../data_layer/data_process/wt_telemetry.py) 的多发动机通道可能取最大值，不能描述成某台发动机的读数。profile 的类型、映射和阈值覆盖仍有边界，不把出现一个温度字段解释为当前必定过热。
- 直升机 `rotor_rpm` 来源是既有 `prop_rpm` 映射；处理器明确没有实现静态转速告警。VRS 仅消费已有 flag，插件确认次数是**有效观测次数**，不能借海战的独立地图 sample-count 合同写成两个独立成功仪表样本。

本轮 [合成证据](../../archive/p2-selection-20261029/selection-evidence.json) 复用现有代码检查六段陆战序列与四次燃油观测：开局 0 无耗尽标记；正数→0 可出现标记并经确认形成候选；12→3 可标记偏少；补弹第一帧旗标已解除但 Detector 可能仍在退出确认；负数/缺失在 P1a 保持未知；燃油不变时余时估计可保持不变。它们是**选型探查，不是新功能测试或实际游戏验收**，没有实现下文的候选投影。

## 推荐 P2a 的最小范围

推荐解决的问题是：**陆战卡给出待发弹数，但用户无法仅由读数判定当前数据层是否提供偏少/耗尽标记。** 不做时现有检测和活动照常可用，只是这项解释仍要用户理解多层规则；这不是现有检测器失效的结论。

### 输入与展示边界

1. 仅 `domain=ground`。复用 P1a 当前摘要里 `ammo_first_stage` 的有效整数与来源校验；来源为 ready、该事实为 available 才解释，不能用旧陆战卡“年龄未知仍 ready”的兼容路径放开。摘要整体 partial 时，其他字段缺失不妨碍一个有确证来源的待发弹事实。
2. 在内部最多读取当前 `processed.flags` 中 `ammo_low` / `ammo_empty` 两个严格布尔值；非法容器/类型降级，不能依赖宽松 bool/string 转换。仅返回固定说明代码，**不向前端/模型复制 flags 集合或 raw payload**。标记缺失只表示未取得正向标记，不能证明数据层某个内部基线、保护窗或失败原因。
3. 在现有陆战卡待发弹行附近显示一段固定说明，复用现有值和活动入口，不另造重复仪表卡。设计最多七个固定状态，冲突/来源失效优先收起结论；不创建历史数值轨迹。

| 设计状态 | 可以说明 | 不能说明 |
|---|---|---|
| source_unavailable | 来源当前不可用于解释，等待新数据 | 缓存旧值、跨域数值、缺年龄当新鲜 |
| count_unknown | 当前待发弹数量未知 | 未知就是 0，或没有待发弹架 |
| conflicting | 当前数量与标记不一致，暂不解释 | 两旗同时真、正数与耗尽旗冲突时任取一条 |
| zero_unconfirmed | 当前读数 0，未取得一致的耗尽标记 | 必定未见正数基线、全车无弹、确认未打空 |
| empty_flagged | 当前 0，数据层给出耗尽标记；候选/输出见活动 | 两次确认已完成、已选中/已播报、装填速度已测 |
| low_flagged | 当前为正数，数据层给出偏少标记 | 满弹容量、精确余量百分比、还能开火多少次 |
| observed_count | 当前读到 N 发，未取得一致的偏少/耗尽标记 | 弹量充足/正常、已补满、Detector 已重武装 |

状态表是待实现设计，不是本轮新增 API。负数、小数、bool、NaN/Infinity、超规格字段仍保持未知；`ammo_low=true` 配 0、`ammo_empty=true` 配正数或两旗同时真作为冲突，不强行“修正”上游。缺失旗标与显式 false 不生成正常/安全结论。

4. 不读取 `_ammo_max/_ammo_baseline_seen` 等数据层私有缓存，不增加历史缓存或检测计数；“读到 0”“数据层标记”“Detector 候选”“仲裁/投递/声音”是不同事实。补弹一帧清旗不表示两次退出已完成，刷新 UI 不得 feed/reset FSM。
5. 过期/未知年龄/未来时钟、离线/离场/阵亡/回放、切域/新生命均按现有可信来源规则隐藏旧解释。载具独立生命绑定仍标 unverified；只因展示本次快照，不宣称已新增来源生命校验。
6. 不扩展 P1a 白名单或 P1b 参数/结果/工具定义；解释仅在面板，三视图的语义、默认关闭/角色绑定、5 秒冷却/并发 1/2 秒 SDK 超时与 1200 字节预算保持原样。也不开放具体历史未播原因。

以下是**未来实现的建议预算，尚未性能实测**：

- CPU/内存：每次既有 dashboard 读取只做一次常数级白名单投影；最多一个固定对象/七状态，序列化目标 ≤512 UTF-8 bytes；不把序列化字节数当 Python 堆内存上限。不新增跨帧缓存、ring、FSM、轮询、线程、网络请求、服务或持久状态。
- 性能验证目标：单独的新增纯投影在 1000 次暖态合成调用中 p95 ≤2 ms；测量环境与范围回填，不将该目标当已测结果或完整面板/SDK/模型时延承诺。
- Token/模型：方案 A 新增定义/参数/工具结果/提示注入/主动消息/LLM 调用均为 **0**，无新 tokenizer；这仅指本功能新增，不代表整个插件或原 P1b 对话免费。若未来扩展 B，重新评审 S/I/A/R、历史重发和普通回复成本。
- 依赖/接口：新增 Python/Node 包、HTTP/SDK 主合同、数据文件为 0；面板沿用现有中文文案与既有组件，不新建国际化 key 系统。若实施触及任何 i18n key，按项目约定同步全部八 locale。
- 默认开关：A 作为原陆战卡的只读说明随有效陆战状态显示，无新持久设置、模型入口或真实输出开关；数据不可用时明确未知，不自动打开任何播报。B 的开关必须另定。
- 核心/维护：推荐只新增纯投影与 UI 接缝，有限语义表和相应回归。若需要改采样合同、阈值、Detector 通用接口或事件策略，说明已超出 A，拆为后续工作；不为维持“低成本”隐瞒跨模块改动。
