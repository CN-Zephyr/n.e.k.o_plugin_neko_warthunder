## P0 Data-Layer Findings And Fix

### Ground role-state flags are not trustworthy

- Live full-crew baseline was `crew=4/4`, `gunner_state=0`, `driver_state=0`.
- During damage/crew replacement the role values changed through combinations such as `3/0` and `1/1`, then returned to `0/0` after respawn.
- Therefore these fields are not a stable `0=disabled, 1=active` boolean contract.
- The processor now uses the confirmed multistate contract: `0=normal`, `1=no replacement`, `2=replacement in progress`; state `3` remains raw-only.
- `gunner_disabled` / `driver_disabled` are emitted only for states `1/2`.

### Laser warning is unverified

- Normal observed value was `lws=-1`.
- The processor now follows the client UI state contract: `-1=absent`, `0=standby`, `1=active warning`, `2=damaged`.
- `laser_warning` is emitted only for state `1`; genuine illumination still needs a live sample.

### First-stage ammo needs a valid baseline and respawn protection

- A same-match respawn briefly produced `ammo_empty` while the indicator block was initializing.
- Negative/missing ammo now clears validity and never alerts.
- `ammo_empty` is latched only after a positive baseline transitions to `0`.
- Same-match respawn now resets the processor and restarts the 10-second spawn suppression window.

### Reliable ground fact

- `crew_current / crew_total` tracked real damage (`4/4 -> 3/4 -> 1/4`) and remains available in the DTO/panel.
- Product policy now keeps crew, role, and first-stage-ammo facts silent; only a real laser warning may become a ground status speech candidate.
