日期：2026-10-29。评审当时结论：**评审完成，接口与开关尚未实现、未启用**。本轮读取当前插件/实际开发宿主源码，复用 P1a 合成摘要做本地序列化与 token 计数，只更新开发文档。没有注册工具、启动服务、调用模型、发声、同步宿主、重建 RC、commit/push 或发布。

## 建议与决策状态

建议后续采用 **B：一个可选、默认不注册的 SDK 只读 LLM tool**；其说明内核复用 P1a `trusted_facts`，面板继续作为零模型成本的查看/降级入口。工具只查询当前状态、可用能力和当前输出策略，不开放操控/开关/自由文本/历史战局推断，不再通过 `push_message` 新建一条解释播报。

这是一份可供选定的实现方案，**不是已经授权开启工具或接受新 token 成本**。P1b 评审与 P1b 代码实现分别记录；待选项见末尾决策表。已跳过的真机项不作为该实现分支的前置条件，未知语义仍不转成事实。

当前 P1a 已有概览摘要和活动页跳转；不足在于用户尚不能在普通对话中可靠地读取同一份受限事实。继续维持面板模式也可用，只是需要玩家切到面板；这就是新增入口需要解决的具体问题，不以新增常驻战术 AI 为目标。

宿主源码证据使用本工作区相邻 N.E.K.O，属于当前 checkout 核对，不宣称所有已发布宿主/SDK 版本都有该能力。当前插件声明的 SDK 兼容范围没有因此修改；实现时需 capability detection 与旧宿主降级验证，不能无条件 import 新装饰器导致旧宿主无法加载。

海战结果对照已有局部 trace 关联与实际候选/仲裁/记录链路，仍供现有面板使用；这不等于四域通用事件因果查询已经存在。若后续把该局部对照接入问答，应单独定义关联选择、生命隔离和时效，不能把首版的受限范围写成“现有系统完全没有事件对照”。

## 接入方案比较

| 方案 | 体验与接口 | 计算/token/维护成本 | 建议 |
|---|---|---|---|
| A 保守/延后：仅面板 | 使用现有摘要和活动页；必要时加确定性文案，无模型问答 | 新模型调用与 token 为 0；没有额外注册与角色生命周期 | 保留为默认和不支持工具时的降级，不把它描述成对话问答完成 |
| B 有界按需工具 | 用户明确启用后，通过 SDK 注册一个当前角色的只读查询；模型在普通用户对话中选用 | 一份工具定义可能随模型请求携带；调用才返回小结果，模型仍需继续生成回答；增加注册/注销和少量限流状态 | 推荐后续首版，默认不注册，先做可审计的输入/结果边界 |
| C 完整/常驻上下文 | 周期把摘要 push_context(read) 或每轮自动注入 | read 不立即回复也占上下文；重复快照与旧值清理增加成本，需处理切域/生命/聊天历史；每 tick 注入尤其浪费 | 不纳入首版；已有场景 read 提示不是持续遥测推送通道 |
| D 显式按钮生成解释 | 点击后 push_message(respond)，再由角色主动解释 | 新增独立模型回复和投递链，需另定暂停/静默/新鲜度/声音语义，可能与普通聊天抢占 | 暂不采用；不能因按钮是显式动作就宣称不影响真实输出 |

### 推荐 B 的调用流程

1. 用户在插件侧明确启用本次会话的按需解释（建议为独立会话开关，默认关闭；名称是拟议能力，当前不存在）。启用时确认一个目标角色，未确认则保持不注册，不能降级为全角色。
2. 使用现有 SDK register_llm_tool 注册一个工具，拟名 `warthunder_get_current_facts`；只接收 view 枚举 `status` / `capabilities` / `output_policy`，不接收用户原话、角色名、域/载具指定、URL、任意字段名、事件 id 或开关参数。handler 必须自行拒绝未知字段，不能只依赖模型 schema。
3. handler 读取当前插件状态并重新走 P1a 投影，再按 view 选字段。使用已有缓存状态，不额外请求 :8112/8111、不刷新检测/队列，不借导入数据层取得更多信息。dashboard 现有路径可能读取既有本地设置/静态缓存，不把它宣称为零磁盘 IO。
4. 返回带读取时间、来源年龄/绑定状态、unknown/失效状态和语义限制的只读结果。状态查询可直接复用完整 trusted_facts；其实际样本体积已经很小，不为几十 tokens 的节省另建一套事实解释器。capabilities/output_policy 可选小视图。
5. 结果通过原 tool result 回到正在进行的用户对话，由当前角色正常回答；插件不调用 Dispatcher、不额外调用 LLM、不推主动消息。普通用户回复可能按宿主聊天/TTS 设置发声；这不等于战斗播报闸开启，本轮未实际实现或发声。
6. 本地停用/插件停止立即令 handler 拒绝新读取，再通过现有 unregister/clear 清理。显式重新绑定角色应先撤掉旧角色；首版不承诺自动跟随角色切换。注册失败或 SDK 缺能力时退回面板，显示“未可用/已请求注册”的真实状态，不报虚假成功。

角色 scope 是工具可见范围，不能当作回调中的强身份凭据。普通 handler 没有可信的用户轮次 id，因此“仅用户问时调用一次”是工具描述/模型行为约束，不能写成插件已能硬性验证。建议首版加插件全局 5 秒冷却、并发 1、忙时返回短固定码且不重试；这可以限制成功读取/计算频率，**不能阻止模型持续尝试工具产生的 token**。若产品要求严格一次性用户授权，先选 A，或另行评审通用宿主授权能力，不能伪造用户轮次证明。

工具启用、停止/重启及显式重新绑定时才做注册维护，不在 0.4 秒遥测轮询里同步工具。SDK 旧版本/部分注册/注销失败/模型不支持工具均须有可见降级；不存在工具时，角色也不能凭旧摘要冒充最新战局。

## 首版事实范围

| 查询 | 允许使用的 P1a 内容 | 不能推断或补充 |
|---|---|---|
| 当前状态 status | domain/status；source age/life_binding；当前摘要中 available 的至多五项数值/布尔，未知字段仍明确未知 | 不重新算 flags/阈值、不用 profile/Datamine 补缺失实时数据；不把 vehicle unverified 改成独立生命绑定已确认 |
| 可用能力 capabilities | 固定能力/限制代码与来源可用状态；按当前域解释“已有能力”和“当前数据是否可用” | 不能把能力存在说成当前检测命中、获得输出授权或模型/TTS 已回复 |
| 输出策略 output_policy | 当前 dry-run/暂停/检测开关及 ground/V2 开关；VRS/海战硬禁播边界 | 不能从当前开关还原过去一次事件的仲裁、冷却、投递或声音结果；不把 pause 当普通聊天已被宿主静音 |
| 特定未播/过去发生了什么 | 只说明当前能确认的策略，并引导已有活动页逐条对照 | 首版不暴露全量 observe/ring，不把 last_decision 当用户指的那条事件；通用跨域因果关联能力另评审 |

| 域 | 可解释事实 | 保留的语义边界 |
|---|---|---|
| 固定翼 | IAS、Mach、AGL、MSL、燃油比例，按 P1a 有效性输出 | AGL 不等于海拔；不由剩油比例预测剩余时间；不以 read tool 开放受限 V2 |
| 陆战 | 乘员/总员、一级待发弹、LWS 设备状态、稳定器、档位 | 待发弹不代表全车余弹/装填速度；LWS 不证明导弹来袭；岗位仍不产生新播报 |
| 直升机 | 旋翼转速、AGL、升降速度，下降负号保留 | 不开放 VRS flag/转速告警，不把读数解释为已证实涡环或指挥自动动作 |
| 海战/未知域 | 既有地图可见敌友/空中图标数、平面距离/绝对方位；unknown 仍未知 | 不确认敌舰/空袭/锁定；不返回未验证仪表、舰员/弹药/舰体/进水、静态型号参数或生效改装 |

明确排除玩家名、原始 chat/HUD/combat、raw payload、完整 flags、battle/life id、异常堆栈/URL/本地路径和完整静态资料。view 不允许把这些字段“按需展开”。工具返回值可进入宿主对话历史，故只能包含已批准进入对话的白名单事实；不能把整个 dashboard 复制给模型。

### 新鲜度与失败回答

- 每次实际执行重新投影，不复用上次工具结果。5 秒是当前来源年龄阈值，不是保证未来 5 秒不变的缓存授权；切域/新生命立即改变事实范围。
- 保留 P1a 的未知年龄、未来时钟、过期、离线、等待、阵亡、回放和部分字段缺失状态；失效时不携带旧数值。读取时间用于识别历史结果，不包含游戏战局标识。
- 超时/停用/不支持/忙时返回固定短错误码和面板指引；不能自动启动游戏/数据层、自动重试模型、回退到旧缓存或暴露异常字符串。
- 模型回答优先一句状态加必要限制；不要求按战斗事件的 28 字单行合同强截用户主动问答。建议短答 1–3 句；这是 prompt 偏好，工具不能给最终回复/TTS 强设独立上限。
- 当前策略可解释不依赖来源有效，但必须说明这是“开关/策略”，不是实际事件因果。没有可关联记录就回答无法确认，不编造 cooldown、锁定或阵亡原因。

## Token 与资源成本

### 本次离线实测

使用 P1a 保存的 157 个**合成** dashboard 状态，只提取 trusted_facts；3 个候选 view 共计 471 个序列化样例。宿主已有 tiktoken 0.14.0，使用本地缓存的 o200k_base，禁止编码表下载；没有调用 LLM 或模型计费接口。cl100k_base 缓存缺失，未下载、未冒充完成跨编码验证。报告见 [token study](../../archive/p1b-review-20261029/token-study.json)，安全候选见 [样例](../../archive/p1b-review-20261029/candidate-examples.json)。

| 内容 | o200k_base 实测 tokens | UTF-8 bytes | 说明 |
|---|---|---|---|
| 单工具定义（含短描述/schema） | 106 | 460 | 是候选 JSON 定义，不含 provider 特有封装 |
| 固定新鲜度/事实边界说明 | 55 | 219 | 仅在设计的请求中携带，不能每 tick 注入 |
| 原 P1a trusted_facts 本体 | 176–219 | 本次主报按 tokens 比较 | 本来已很小，不需要再复制一个阈值/检测模型 |
| status 小视图（含 output/is_error envelope） | 139–178 | 456–647 | 单个来源/至多五项事实，保留未知与限制 |
| capabilities 小视图（含 envelope） | 93–113 | 321–400 | 能力与限制仍不等于实际触发 |

这些是**候选序列化文本的本地编码计数**，不是已实现工具的线上用量、总请求成本或性能测试。直接复用原摘要与小视图的样本不同封装也不完全相同，不能将差值包装成端到端 token 节省比例。真实供应商可能使用其他 tokenizer/缓存/音频与推理计费，不能据此给出金额或保证总账单上限。

### 建议预算与计费模型（待拍板，不是现有门禁）

| 项目 | 建议约束 | 可执行性/限制 |
|---|---|---|
| 默认不启用 | 不注册 schema，不做按需调用/额外 prompt 推送 | 初始关闭时本功能增量 token 为 0；停用后残留的旧历史/尚未撤掉的 schema 不保证立即归零 |
| 工具定义 | 目标 ≤160 tokens；固定边界说明 ≤80 tokens | 按开发时选定 tokenizer 验证，不新增高频 tokenizer 依赖 |
| 参数 | 一个 view 枚举，序列化 ≤128 bytes，目标 ≤32 tokens | 运行时拒绝未知/超长参数，不回显原输入；schema 不能替代 handler 校验 |
| 返回体 | 序列化 ≤1200 UTF-8 bytes 且本地预算目标 ≤320 tokens | 运行时可硬限制 bytes/字段数；跨模型 token 硬上限不能靠这个代理保证。超额按整字段降级为固定未知，不截断 JSON/单位/限制或泄漏片段 |
| 调用频率 | 描述建议用户轮次一次；插件全局 5 秒冷却、并发 1、无自动重试 | 插件能限 handler 读取，不能证明真实用户轮次，不能保证整个会话不会重复工具尝试 |
| 超时与耗时 | SDK 注册超时建议 2 秒；handler 暖态 p95 目标 ≤50 ms | 是后续验收目标，本次未测 SDK 调用延迟；不保证网络/模型完整响应两秒完成；不启动新数据层或后台任务 |
| 最终回答 | 建议 1–3 句，设计估算留 160 output tokens | 只是短答目标；普通宿主生成/推理/声音成本受原模型设置控制，工具无法独立强制 |

有工具调用的一轮新增成本应按：**本轮携带的定义 S + 边界说明 I + 调用参数 A + 结果 R + provider framing + 继续生成的回答/推理/音频**核算，还要加上既有 system/persona/用户历史与历史工具结果重发。不能只算 R，也不能把同一轮已有历史从总账单中扣掉。

以小视图 status 的实测最大 R=178 计，S+I+R=339 tokens，尚未含参数/封装/回答等。若采用原摘要 219 tokens，则三项约 380 tokens（不含 envelope）；两者均只是一轮新增输入片段的比较。建议开发预算的 S/I/A/R 之和是最多 592 个代理 tokens（160+80+32+320），**不是总调用硬上限**。

定义开销不能忽略：例如 100 次文本模型请求都携带该定义，单 schema 即约 10,600 个本地代理 tokens，即使一次也没调用工具；是否缓存收费按 provider，实时会话的 schema 更新/计费也不能套成每个音频包一次。若每次查询结果约 219 tokens 且一直保留，理想化的 10 轮全量历史重发累计会出现 219×(10+9+…+1)=12,045 个“结果片段”tokens，未计定义/其他历史，也未假定实际宿主压缩策略。这说明历史回灌可能大于短 JSON 的局部节省。

计算/内存方面只接受固定行投影和少量会话开关/冷却状态，不新增轮询、进程、长期缓存、向量库或插件内 LLM；SDK/HTTP 复用宿主已有能力。当前插件 Python dependencies=[] 不因评审改变，离线计数使用的是宿主已有依赖与本地缓存，不把 tiktoken 加入插件运行包。若实现需要新的 tokenizer/上下文维护或通用宿主改造，应重新评审成本。

## 真实输出、暂停与隐私边界

- 读取工具不是 BattleEvent，不进入 Detector/Scenario/Arbiter/Dispatcher，不更新输出限流时钟，不调用 set_dry_run/test_say 或 push_message。
- 乘员/弹药、受限 V2、VRS、两类海战事件与 free-text 的真实输出规则原样保留；工具不能让模型绕过这些限制“补播”警报或原文。既有战斗场景 read/respond 合同不因本评审改写。
- 用户主动对话的普通回复是否走 TTS，由宿主聊天设置决定。必须在实现前明确同意“战斗 dry-run/暂停并不等于普通问答静音”的交互语义；若要求所有声音都静音，应选纯面板或使用宿主已有静音设置，不伪造插件能拦宿主音频。
- 本地诊断只记录固定状态/计数，不记录用户问题、参数原文、prompt/模型回复或数值轨迹；不额外保存新的摘要历史。宿主自身对话历史承载安全工具结果的事实必须告知并纳入成本判断。
