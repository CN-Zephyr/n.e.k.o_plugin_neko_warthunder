## 这轮最重要的一件事：样本能验证的比我们以为的多

`local_samples/archives/` 里的归档含**完整的 8112 快照流**（含 `combat` / `hud_events` /
`situation` / `proximity`，身份已解析、有归属击杀、有阵亡与重生）。把它解开回放，本轮多个改动
从"理论上对"变成"数据上证实"，并且**纠正了两处此前基于合成用例的错误判断**。

解压方式：任意解压工具解到 `local_samples/`（该目录被 gitignore），约 670MB。

### 被数据证实的

- **交火压力误判**：旧规则按全场 `hud_events` 计压力，实测两段完整对局中
  69.1%（1591/2303 帧）与 51.3%（2547/4969 帧）的时间被误判为本机在交火，期间 `low_fuel`
  与陪伴类输出被压制。改按归属条目后降到 9.2% / 4.3%。
- **仲裁缓冲浪费**：仲裁选中的事件约五分之一在推送前因过期被丢弃（33→10 丢 8、36→12 丢 8、
  40→16 丢 6）。加入入窗前的新鲜度判定后，真实推送 10→11 / 12→13 / 16→17，过期丢弃降到
  0 / 0 / 2，且构成变好（`low_alt_danger` 2→3、`spawn` 1→2，此前被饿死的安全提示发得出去了）。
- **`low_fuel` 重复播报**：每段样本都发 3 次，其中一段 13 秒内三次。加 `once_per_battle` 后
  每局恰好 1 次，其他事件计数一个没变。

### 被数据纠正的

- **危急心跳阈值调错了**。首次实现取 8 秒，但实测 critical 段最长只有 6.9 秒
  （`low_alt_danger`；`stall_risk` 6.3s、`high_aoa` 3.4s、`low_fuel` 3.0s、`overheat` 0.2s），
  该机制在真实飞行中**永不触发**。改为从 `critical_preempt_cooldown_seconds` 推导（默认 5 秒）
  后，样本里救回一次真实的漏报：`t=297.0` 低空告警播报、`t=302.9` 失速进入其冷却窗——
  玩家贴地失速而副驾驶全程没吭声。
- **"重生重播整局击杀"的严重度被高估了**。合成用例能复现，真实录制不能：`combat.feed` 是
  `deque(maxlen=100)` 且喂它的是全场伤害流，实测**阵亡后 41 帧（约 9 秒）**玩家自己的击杀
  就被挤出窗口，而两段样本的阵亡分别持续 437 与 1530 帧。新旧引擎回放都是 0 次重播。
  修复仍然正确（零成本消除整类隐患），但触发条件窄：需在最后一次击杀后约 9 秒内重生——
  陆战快速重生或冷门房间可能满足，本次采样的繁忙空战不满足。

## 行为变更清单

插件侧：

- `DetectorEngine` 引入 `dead_state_policy`。消费整局持久 feed 的检测器（击杀 / 接近 /
  无线电 / HUD 通知 / 自由文本）阵亡期间改为"喂帧推进游标、丢弃产出"，不再重置游标。
- `_sync_game_context` 退出分支去掉 `was_active`，恢复推送失败一次后不再永久卡死。
- `startup` 在旧轮询线程仍存活时拒绝启动；旧线程退出后，新线程使用独立的
  `threading.Event`，避免 join 超时线程被复活或与新循环重叠。
- `set_dry_run` 增加会话内覆盖，不再被无关 `config_change` 静默回滚；**刻意不持久化**（见下）。
- 危急条件在持续期按心跳重发（见上）。
- `COMBAT_STRESS` 的 damage 压力改看归属条目。
- 仲裁单槽窗口入窗前判新鲜度，注定过期的记 `expired_before_flush` 并让出槽位。
- `low_fuel` 启用 `once_per_battle`。
- 文本消毒按 Unicode 类别（`Cc`/`Cf`/`Zl`/`Zp`）拦截隐形字符，并覆盖常见中文注入短语（只收紧）。
- repeat-collapse 签名对连续值分桶（距离 250m、温度 10℃），此前原始浮点漂移使折叠形同虚设。
- 插件同时发出宿主已在消费的通用投递字段（`delivery_ttl_seconds` / `delivery_intent` /
  `interrupt_policy`），详见 `host-callback-contract-reservation.md`。

数据层：

- 告警抑制窗口一并重置派生的 `level`，不再返回 `{"level": "critical", "alerts": []}`。
- 回放判定加入午夜回绕保护。`game_time_sec` 是座舱时钟的当日秒数（0–86399），夜战跨 00:00 时
  会从 86399 跳回 0，旧判据会把整局锁成 `replay`（告警/战绩/态势/嘉奖全停）。
- 冷启动首次 HUD 排空失败时不再保存 `{0,0}` 恢复游标，避免把上一局残留当本局击杀。
- `TelemetryService` 的周期等待改为可中断；若 worker 因 I/O 阻塞超过 join 时限，
  服务会保留线程引用并拒绝重启，直到旧 worker 确认退出。
- 录制器加会话总量上限（默认 2GB 未压缩，超限自动停录并在 `status`/`meta` 标注 `stopped_reason`）。
- 删除零调用且危险的 `WarThunderClient.to_meters`（用 `grid_size` 换算会系统性低估约 2.5 倍，
  正确实现在 `wt_geo`），以及 `drain_hud` / `drain_chat` / `reset_incremental_cursors`。
- `TelemetryProcessor.resolve_profile()` 成为公开入口，`wt_proximity` / `wt_server` 不再
  import 私有 `_merge_profile`、也不再 `getattr(processor, "_family_rules", [])`。

面板：

- 加入 6 秒可见性感知轮询，并串行等待每次刷新完成、吞掉后台刷新失败，避免请求重叠和
  未处理的 Promise rejection。此前面板**没有任何自动刷新**，数据在用户交互之间完全冻结，
  而诊断页却写着"按当前状态实时更新"。
- 身份弹窗三个入口统一走重置逻辑；测试开口后刷新诊断链路；`conn_state` 恢复三态显示；
  状态卡改用 `data-tone`（此前 `wt-status-warning` 类根本不存在，靠基础样式侥幸正确）。
- 可访问性：标签页补 `role="tablist"/"tab"` 与 `aria-selected`；播报频率选中态改用视觉隐藏
  文本（UI kit 的 `Button` 会静默丢弃 `aria-pressed`）。

## 明确的产品决定（不要"修"）

- **`dry_run` 不跨重启持久化**。开启战斗播报被当作每次启动插件时的一次显式启用动作，
  所以每次启动都是静默的。同组的插话策略 / 播报频率 / 播报类别 / 昵称都会持久化，唯独这一项
  刻意不落盘。若将来要改，需同时调整 `release_defaults_gate` 断言的语义。
- **回复长度归角色人设，不归投递层**。`short_tts_line` / `max_reply_chars=28` 是写进 prompt、
  由 `target_lanlan` 指向的角色执行的约束，不是等宿主强制截断的契约。不要提议让
  `callback_render.py` 按 metadata 截断——那是把角色的事塞进投递管道。metadata 里的同名字段
  只作真机排查的可观测标记。
- **两个身份不要混淆**：`player_name` 是玩家手填的战雷游戏昵称，只给数据层判
  `is_my_kill` / `is_my_death`，不进 prompt；`target_lanlan` 是哪个角色回应，自动跟随当前
  活跃角色，插件不设默认值。
- **两条尾随确认阈值刻意不同**（帧驱动 5s/1500m，事件驱动 8s/900m），别在调参时对齐。

## 宿主侧现状

后续核心研究已确认，插件不能依赖直播工作树里曾经存在、但没有形成 upstream 公共契约的
`deferred_candidate` 路径。被动语义只认 `ai_behavior="read"`：只作为之后自然用户轮次的
背景，不主动创建回复或 hot swap，也不保证角色会提及。

因此，文本聊天静默窗内的确认击杀现在改为 `read` +
`delivery_intent="passive_context"`；不再发送 `candidate_ttl_seconds`、下一回复消费提示或
`deferred_candidate`。`delivery_ttl_seconds` 与 `interrupt_policy="drop"` 仍作为通用、
前向兼容的投送提示；旧宿主不认识时必须安全忽略。`dispatcher_pushed` 只表示
`push_message` 已接受，不能解释成已生成或已播放。

危急提示能否硬切已经开始播放的告警仍是宿主音频播放层能力，插件 metadata 无法实现。
当前不为战雷加入宿主特判；是否需要通用硬打断能力，继续由真机延迟证据决定。
