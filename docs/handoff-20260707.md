## Mode Boundaries

- Fixed-wing condition events are air-only: `stall_risk`, `high_aoa`, `over_g`, `low_alt_danger`, `overspeed`, `low_fuel`.
- These events must be silent in `ground`, `naval`, `heli`, and `unknown` domains, even if old samples or fallback DTOs carry matching flags.
- Ground mode now has its own non-critical cue set:
  - `ground_laser_warning`
  - `ground_crew_loss`
  - `ground_ammo_empty`
  - `ground_ammo_low`
- Ground cues only trigger under `domain == "ground"` and do not enter fixed-wing `CRITICAL_RISK`.
- Sea and helicopter modes still need their own future event matrices; do not reuse fixed-wing safety logic for them.
- Prompt output is also mode-pinned. Event payloads should keep `domain`; `NekoDispatcher` writes a `当前模式` contract into prompts, and real pushes also include `metadata.domain` plus `metadata.domain_prompt_contract`.
- Current prompt roles: air = 后座/僚机, heli = 机组搭档, ground = 车组搭档, naval = 舰桥观察员. Ground output should use 上车/出击/车组/装填/掩体/看路 language and must not borrow 升空/后座/云霄/机翼/拉杆 wording.
- The persistent War Thunder context now says that if an event includes `当前模式`, the model must obey that mode only; if no mode is present, it should not guess the vehicle type.

## Output Policy

- Default config remains dry-run first: `dry_run=true`.
- Urgent safety/action cues use deterministic plugin-owned short lines for speed.
- Flexible events such as spawn, kill/death, overheat, low fuel, generic proximity, objective cues, and battle end use bounded `respond` prompts so the cat can sound less templated while staying inside factual boundaries.
- Free-text sources (`hudmsg`, raw `combat.feed`, `awards`, raw HUD notices) remain dry-run-only and sanitized. Do not enable real speech for them without a separate dry-run safety pass.
- V2 evidence-gated events (`enemy_on_six`, `tailing_risk`, `ground_target_nearby`) remain real-output guarded until live evidence is complete.
