# 聊天活动读取兼容修复

2026-10-30：实现、review、离线回归及备份同步完成；未 commit、push、发布或重建 RC。没有启用/重启实际插件，没有修改宿主核心或输出开关。

## 修复内容与最终方案

插件不再寻找 SDK 未公开的 memory.get_sync，改用公开 get(bucket_id=当前角色, limit=1, timeout=0.25)。通过公开 dump 读取活动记录，并兼容旧 SDK 返回的 value 包装以及宿主记录 dump 中的 raw 字典；最多展开四层，循环或畸形结构安全放弃。不读取 SDK 私有 namespace，也不把宿主核心补丁整份带入插件。

角色与 user_message 类型校验保持；明确的其他类型/其他角色不会通过嵌套数据被重新解释。时间戳必须为有限正数，旧时间和相同时间不会覆盖新活动。查询和 dump 异常保留原活动模式；在异步 owner loop 中提前降级，不发起同步请求或创建未等待的协程。

此方案是在[前期研究](../../archive/chat-activity-research-20261030/research-report.md)后补充验证得到的兼容方案：最初候选只读顶层 dump，所以需要宿主转换修复；最终插件通过旧记录的公开 dump 即可取得活动字段，旧 SDK 三种形态已实测通过。宿主转换修复仍值得独立维护，但不是这版插件读取旧封装的必要前置条件。宿主跨循环通信可靠性仍属独立依赖，插件不绕过其 RPC，也不能宣称所有实际宿主版本已经验证。

修复恢复的是聊天避让策略：近期 text 聊天的击毁事件可作 read 被动上下文；voice 聊天保持静默窗抑制；no_interrupt / critical_only / allow_interrupt 沿用既有行为。没有增加播报、模型调用或告警权限；与 8111 的 indicators 无效、地图对象解析失败是独立问题。
