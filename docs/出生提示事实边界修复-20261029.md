## 现场反馈与证据

用户报告开局听到“我们升空了”，未明确这几次开局时的实际载具。此前依据更早的陆战片段将其称为陆战开局，证据不足。2026-10-29 17:33:23 的宿主插件日志显示，出生提示本身包含“当前模式：空战/飞行”和“可用语境：上机、升空、跟上、护住你”，不是仅凭用户听感推测。现场安装副本的派发器、生命周期检测器和常驻场景提示均与修改前源码 hash 一致。

后续北京时间 20:05 左右用户确认正在空战、驾驶波-2“夜魔女”，与独立采集器当前 air/po-2_nw 一致；这是当前场景标注，不能用来判定历史几次出生识别正确或错误。

这说明提示词确实提供了未经出生事件证明的动作暗示。当前源码原本已有四域角色分支，并非完全缺少陆战文案；为何这一时刻事件携带 air 域，现有历史日志未保留同帧 8111/domain 来源证据，仍未确认。之后读取到 tank/ground 不能倒推当时的字段，也不能据此声称域识别已经修复。

## 修改与评审

- 移除四域出生提示中的动作示例（升空、起飞、悬停、出航、装填等），保留事件携带的域与对应伙伴角色。
- 出生事件仅确认进入战局；只有 `respawn is True` 才确认完成重生。明确事件不证明载具运动状态，不能宣称已执行未提供的动作。
- 出生事件改用确认事实的语境约束，其他飞行安全等具体事件继续采用原域措辞。
- 不增加固定台词、模型调用、检测器、告警或输出权限。人格仍决定最终表达；提示词约束不是模型绝不会偏离的证明。

按本轮备份逐行评审派发器和两个测试文件的增量，保留全部原有未提交修改。遥测→出生检测→派发的新增回归覆盖四域首次入场/重生，陆战和海战使用 `/state.valid=false` 的路径，检查域传递、事实限制和真实投递参数。
