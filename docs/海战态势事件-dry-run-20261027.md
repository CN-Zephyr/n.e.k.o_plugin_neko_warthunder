## 范围、成本与方案

用户明确要求先做海战专项态势 dry-run，真实输出关闭。采用保守方案：只记录已确认海战中的敌方图标类别出现，不引入距离阈值、目标身份跟踪、舰种、锁定、空袭或航向推断。完整舰艇安全/态势输出需要另定字段和证据；若延后本轮，维持地图卡而没有专项候选/决策记录。

两个固定大小的 detector 状态和常数级来源/计数检查复用已有地图轮询，新增轮询、目标扫描、后台进程、依赖、配置、持久状态及 LLM/token 调用均为零。事件复用现有最多 20 条活动摘要，不修改数据层阈值、宿主核心或 Scenario 危急集合。

## 两类事件与确认策略

| 事件 | 图标类别 | 参数与真实输出 |
|---|---|---|
| `naval_map_contact` | 敌方总数减空中数大于零，表示水面/地面图标类别存在 | map_awareness、priority 3、severity 2、30 秒冷却、4 秒事件时效；非抢占，仅 dry-run |
| `naval_air_contact` | 敌方空中图标数大于零 | 同上；不确认空袭/威胁、距离、高度或锁定 |

- 仅在线、在战、存活、非回放、`domain=naval` 且有效 `ship/fleet`、`domain_source=indicators_army`。此前“无仪表保持 unknown”的边界不变；ship/fleet 当前游戏正向证据仍未验。
- 要求当前 battle/life、有效自身位置、合法非负整数聚合计数，空中数不能大于敌方总数。数据层只将 aircraft/ground_model 作战单位计入这些计数，任务标记不算敌方单位。
- 使用 `meta.map_objects.count/age_sec/life_index`，不是轮询尝试时间或 fast tick；来源年龄连同缓存流逝时间不超过 5 秒。缺元数据、旧生命、无自身位置或非法计数时不检测。
- 每类 **2 次不同成功地图采样确认进入、2 次有效消失采样后重武装**；持续存在不按数量或目标身份变化重报，没有 recovery/心跳。重复成功计数不推进进入或退出确认。
- 来源失效立即重置；battle/life 变化、成功计数回退、源时间回退，或两个观测到的成功样本间隔大于 5 秒时重新确认，不能跨未观测中断凑齐两次。
- payload 仅 `domain/battle_id/life_index/map_sample_count`，用于撤销旧候选；不携带原始文本、坐标、目标身份、图标名、距离或数量。活动只保存安全摘要，raw 不进入模型或持久诊断。

## 输出硬边界与 review

真实模式在 Arbiter 的单槽/冷却之前过滤这两类事件，原因 `naval_dry_run_only`；直接调用 Dispatcher 也在构建 prompt/LLM/直出前硬阻断，其他真实输出开关不能绕过。没有新增启用开关。

Arbiter 在处理候选、旧缓冲与失败重试前，复核当前类别、来源时效、battle/life 与成功计数。图标消失、来源失效/过期、计数回退或旧生命时撤销候选，原因 `naval_contact_cleared`；4 秒事件时效仍有效。切换真实模式释放 dry-run 缓冲，不占槽或消耗本事件冷却；不撤回已经写入历史的观察记录。

Review 覆盖成功地图服务→parser→两类 detector→完整 evaluator→Arbiter→Dispatcher→活动页。额外补上长观测间隔/时钟回退后的重新确认；修正 smoke harness 的状态等待和“仅记录”筛选按钮/结果徽标的定位歧义。未发现本轮阻塞问题。
