# 舰艇只读仪表字段矩阵（2026-10-28）

> 六期历史记录：以下保留当时范围与结果；七期已补独立采样边界和固定来源证据，当前状态见 [七期记录](舰艇独立采样与字段证据-20261029.md)。真实舰艇语义/读数仍未验证。

结论：当前能确认的是四项通用字段的源码传输路径与只读盘点边界；**尚无经过确认的舰艇仪表读数合同**。代码字段存在、合成测试通过、响应包含数字、实际舰艇支持和物理语义验证是不同证据。真实输出保持硬关闭。

## 来源与证据层次

当前路径：游戏 `/indicators` → `WarThunderClient._parse_indicators()` → `Indicators` → `Telemetry.to_dict()` / `TelemetryService.get_snapshot()` → `/api/telemetry.indicators` → `BattleState.raw` → 插件只读字段盘点。仪表字段不进入 naval 的飞行/陆战 processed 派生、检测或数值展示。

源码依据：[解析器与 DTO](../data_layer/data_process/wt_telemetry.py)、[快照与元数据](../data_layer/data_process/wt_server.py)、[HTTP 消费边界](../adapters/telemetry_client.py)、[字段盘点](../adapters/naval_instrument_fields.py)。后端接口中通用字段的单位说明不代表已经取得当前舰艇样本。

本轮对 `local_samples/**/indicators.jsonl` 与 `processed_8112.jsonl` 使用 `--no-ignore` 定向检查，共 8 个文件，未发现小写 `army=ship/fleet` 标记。未读取 HUD/chat 专项流、未输出原始遥测，也没有把有限扫描扩大成“游戏不提供舰艇仪表”。ship/fleet 仍是已有兼容合同代码，当前正向舰艇证据待补。

## 候选字段

| 候选 | 游戏原始键 | 规范化路径 | 当前已知 | 舰艇边界 / 待确认 |
|---|---|---|---|---|
| 速度 | speed | indicators.speed | _num() 直接转浮点；通用文档声明 m/s，raw 保留原始键 | 当前舰艇是否提供、单位、零/倒车符号待验；不当作已验证航速，不转节/km/h，不回退 IAS/TAS 或地图差分 |
| 罗盘 | compass | indicators.heading_deg | 直接转浮点，无舰艇专用角度处理 | 舰艇基准方向、度/弧度、范围/跨零语义待验；不借用地图最近目标方位或 aircraft 朝向向量，不做 mod360 |
| 转速 | rpm | indicators.rpm | 通用 DTO 注释归地面载具；原样浮点 | 是否为舰艇发动机/轴/表针、单位、多机对应待验；不回退 prop_rpm 或 vehicle.engines，不当旋翼或舰轴转速 |
| 控制量 | throttle | indicators.throttle | 通用文档含飞机 WEP/加力语义，原样浮点 | 舰艇控制范围、倒车/车钟、百分比语义待验；不沿用飞机 >1 规则，不缩放或生成控制建议 |

有限数值检查只用于描述“响应里有数字”，不证明物理范围合法。零、负数、小数不会被擅自改成缺失、倒车、停机或百分比；本轮不输出它们的实际值。

## 盘点状态

| 状态 | 含义 |
|---|---|
| observed_numeric | 规范化与对应原始键都是有限、非布尔数字且一致；仅证明响应数值存在，语义未验 |
| normalized_only | 仅规范化数值，没有对应原始键佐证；来源待核 |
| raw_only | 仅对应原始数值，未规范化；不自行补齐 |
| missing | 未提供数值 / null，区别于合法零 |
| invalid | 布尔、字符串、对象、数组、非有限值或不可表示的巨大整数；不接受通用解析器的强制转换结果 |
| conflicting | 规范化与原始数值不一致，或原始显式 null 而规范化有数字；不择一显示 |
| unavailable | 来源失效，不沿用旧可用性 |

来源要求在线/在战/非阵亡非回放、已确认 naval + indicators_army + 严格有效 ship/fleet，且战局/生命头部标识有效；原始容器/有效性/兵种不得与规范化来源冲突。响应时间有限、非未来，按 max(fast age, 当前时间减响应 timestamp) 计龄，超过 5 秒收起旧状态。字段盘点只看当前响应，既不要求地图/vehicle 有效，也不借用它们的成功计数、年龄或生命编号。

## 尚未建立的仪表采样合同

meta.fast 是快轮询元数据，不是独立成功仪表采样证据。timestamp 可限制旧响应的年龄，但不能代替仪表自身的成功样本编号、来源时间与采样生命绑定；响应头 life_index 也不能证明缓存仪表属于该生命。

因此投影明确返回 instrument_values_enabled=false、sample_life_bound=false、naval_semantics_verified=false、real_output_enabled=false。本轮没有新增数据层元数据或更改 HTTP v1.10 合同；后续若要显示仪表值，需要先讨论并定义独立采样及生命周期合同，再确认逐字段语义。

## 不纳入舰艇读数的现有字段

| 字段/来源 | 当前处理与缺口 |
|---|---|
| vehicle.ias_kmh / tas_kmh / mach / engines | 飞行中心字段，无舰艇读数合同，不当航速、轴转速或舰艇发动机信息 |
| crew_current / crew_total、岗位/稳定器/LWS | 坦克语义不等同舰员、生存率、舰艇岗位或设备；保持既有 naval 派生清理，不盘点/显示数值 |
| first_stage_ammo | 一级待发弹不等于舰炮弹药、全舰余弹或弹药库状态 |
| prop_rpm / radio_altitude / vario | 现有直升机/飞机字段，不能凭名称复用到舰艇 |
| water/head/turbine/oil_temperature | 现有飞机温度/多发动机解析及 profile 不能直接变成舰艇温度或过热阈值 |
| 舰体、进水、维修、火灾、弹药库、航海操纵 | 当前无经过验证的舰艇字段合同；不猜键名、数值、告警或操作 |
| speed/crew 推断阵亡/重生 | 舰艇自动重生模型未实现；沿用现有可信 owned HUD 死亡边界，不新增运动/乘员推断 |
| 地图计数/距离/绝对方位 | 沿用已有地图只读边界；属于地图态势，不是舰艇自身仪表，也不能确认舰种/锁定/射击距离 |

## 下一步的证据与实现边界

1. 取得带舰艇类型/域确认的安全样本，只登记必要白名单字段及计数，不收录玩家名、聊天/HUD 原文或完整 payload。
2. 对照实际舰艇原始键和规范化键，确认单位、基准、符号、范围、缺失/null/零、倒车/控制量、多发动机与舰型差异；不能把单舰结果推广为所有舰艇。
3. 先定义仪表独立成功采样、失败/恢复、战局/生命隔离合同；不能拿 vehicle 或 map_objects 元数据充当证据。此合同改动尚未开展。
4. 合同和语义足够后，再定只读数值卡范围及浏览器/Electron 验证；告警、自动重生和真实输出不随字段盘点开放。

N05 实际舰艇/Electron 对照本轮跳过、未验收；当前验证、同步和恢复证据见 [本轮记录](舰艇仪表字段与边界-20261028.md)，当前阶段见 [统一状态](当前开发状态.md)。
