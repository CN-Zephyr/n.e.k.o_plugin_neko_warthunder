## 发现与处理

- 首次构建在隔离安装门禁失败：工具仍要求导出 `default.toml`。当前宿主 `install_package()` 只部署代码，profile 仅供显式 unpack 导出，返回的 `profile_dir` / `profiles_root` 为 `None`。已修正构建器并增加回归后完整重建，未通过跳过门禁生成产物。
- SDK 验证脚本的外部安装命名空间和 Windows spawn main guard 已修正后重跑。成功报告验证加载的是本次隔离安装路径，未以开发宿主副本冒充新包。前两次失败日志保留作诊断；第一次因文件句柄遗留的临时日志目录保留归档，自动审批拒绝其递归清理（`blocked by policy`），无运行进程。
- 官方检查有现存的旧运行配置兼容提示和 ignored `local_test_logs` 历史副本的重复 entry 提示；包检查确认这些目录未入包，生成 metadata 的 entry id 唯一。SDK 有 Windows Proactor/pyzmq selector 兼容提示，实际 route、worker 重启和清理已通过；负向验证中预期的 HTTP 404 不是正常 action 失败。
