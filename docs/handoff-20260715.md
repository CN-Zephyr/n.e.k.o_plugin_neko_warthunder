## Completed Since The Previous Handoff

- Runtime state is isolated across air, ground, naval and non-battle interruptions; mode changes re-arm the relevant awareness detectors without leaking stale state across domains.
- Hosted UI was redesigned around three operator views: an overview for normal use, a filterable activity history, and diagnostics for explaining the runtime chain.
- The activity history is backed by an always-available, in-memory 20-item safe ring. It stores only event/stage/outcome metadata; debug timeline opt-in and raw-text privacy boundaries are unchanged.
- Diagnostics can copy a versioned, allowlisted support summary containing connection, battle-domain, safety, preference and recent decision/output codes. It excludes identity, chat/HUD, targets, vehicles, URL/PID, error text and prompt/payload text.
- First-run onboarding is two steps: set the War Thunder nickname, then learn the small set of persistent controls. It can be skipped and reopened from settings.
- Broadcast start/stop, emergency pause/resume, sound test, refresh, nickname editing and dialogue policy remain reachable without exposing raw telemetry or free text.
- Settings include a one-click recommended broadcast reset; it does not add controls or activity items to the overview screen.
- Panel safety/output status checks are centralized, dead styles were removed, controlled selects no longer carry redundant `selected`, and the duplicate dialogue-policy control was removed from settings. The overview footer remains the single policy control.
- The standalone source now includes the host-integrated context-state, repeat-collapse, preemption and takeoff-protection fixes. The host boundary gate follows the current modular `main_logic` layout and ignores line-ending-only differences when checking the embedded plugin copy.
- Eight plugin manifest locales are present with matching keys. The large Hosted UI body remains Chinese-first for this RC.
- All existing privacy, dry-run, replay, free-text, mode/domain, output freshness and V2 real-output guards remain in place.
- Managed 8112 startup now binds only to the configured loopback host, respawn resets discard the pre-reset processed frame, free-text activity metadata no longer carries source-provided codes, and the standalone tests follow these embedded-runtime contracts.
- 2026-07-16 maintenance closes the browser-facing 8112 boundary: wildcard CORS is removed, loopback `Host` is validated, and identity/record mutations require `X-Neko-Warthunder-Action: 1`; explicitly trusted browser origins can be added with repeatable `--cors-origin` arguments.
- Data-layer health now refreshes from every telemetry poll, managed-process exits are reflected in diagnostics, startup failures close log handles, embedded shutdown closes the HTTP socket, and changing the configured 8112 URL/auto-start setting restarts only the plugin-owned service and restores saved identity after a healthy restart.
- 2026-07-23 maintenance adds stable `battle_id` / `life_index` semantics, confirmed-respawn counters, transient 8111 probe grace, per-match plugin state reset, and corrected horizontal clock reporting. Same-match respawn no longer looks like a new battle.
- Promotion-only relaxed defaults and immediate terminal-output special cases are excluded from formal source. `dry_run=true` and `v2_live_verified_real_output_enabled=false` remain the release defaults, and battle-end output follows the normal arbitration/backpressure path.
- Prompt contracts no longer prescribe a fixed emotional response for spawn, kill, death, or battle end; they constrain only verified facts, domain vocabulary, response length, and non-takeover safety.
